# Kinescope downloader research snapshot

Checked 2026-10-22. GitHub counts and package activity are snapshots, not permanent recommendations. Recheck the project page, release date, dependencies, and current behavior before installing anything.

## Findings

| Project/source | Observed evidence | Decision for this skill |
|---|---|---|
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | Installed host version was 2026.08.19. `yt-dlp --list-extractors` did not list a Kinescope-specific extractor. The Kinescope link used the generic extractor to discover JSON-LD/player metadata and a signed HLS manifest. Its local help documents `--concurrent-fragments` for HLS/DASH; default is 1. | Default for an authorized share/player URL because it is already installed, actively maintained, supports generic HLS, and does not require a Kinescope-specific binary. Inspect this video's formats before selecting streams. |
| [yt-dlp issue #10713](https://github.com/yt-dlp/yt-dlp/issues/10713) | Historical 2024 Kinescope report shows the generic extractor finding a signed `master.m3u8`; the captured URL contains HTML `&amp;` entities. | Useful diagnostic precedent for a 403 after extraction. It does not prove that the exact historical bug remains in current yt-dlp. Unescape the manifest URL and retry with the correct referrer before changing routing or installing another downloader. |
| [anijackich/kinescope-dl](https://github.com/anijackich/kinescope-dl) | At the snapshot: 257 stars, 58 forks, 12 open issues, 5 open pull requests. Latest release is v0.2.2 published 2023-08-16; repository `pushed_at` was 2025-02-12. README advertises automatic best-quality selection and requires FFmpeg plus `mp4decrypt`; the project explicitly supports encrypted video. | Most visible Kinescope-specific CLI found, but not the default: it is behind the installed yt-dlp workflow in maintenance and adds a DRM-specific decryption dependency. Do not install or use it to bypass DRM. |
| [zheka5/ksdl](https://github.com/zheka5/ksdl) | At the snapshot: 0 stars, 1 fork. README describes SAMPLE-AES streams and an `mp4decrypt` step to decrypt audio, alongside N_m3u8DL-RE and yt-dlp. | Not a popularity or maintenance winner, and its decryption pipeline is outside the supported workflow here. |
| [puemos/hls-downloader](https://github.com/puemos/hls-downloader) | At the snapshot: about 2.7k stars, 306 forks; MIT; repository pushed 2026-10-20. It handles generic HLS, concurrent segments, quality selection, and local FFmpeg.wasm muxing. The README marks Chrome MV3 as experimental; other browser builds have their own distribution paths. | Popular general HLS browser fallback when an authorized browser session is needed. It is not Kinescope-specific, may be slower for large files than native yt-dlp/FFmpeg, and should not be installed or granted browser access without the user's request. |
| [Kinescope embedding docs](https://docs.kinescope.com/video-player/embedding/) | Official player docs identify `master.m3u8` as the HLS manifest for custom players/mobile apps and list quality levels through 2160p. | Confirms HLS is a supported integration format. The maximum available quality is per-video; inspect the manifest rather than assuming 1080p or a fixed format ID. |
| [Kinescope Video API](https://docs.kinescope.com/api/video/core/) | Official authenticated `GET /v1/videos/:video_id` response schema includes `assets`, `hls_link`, and optional asset `download_link` values. The request uses a Bearer API token. | For a user with workspace authority and a locally available token, inspect the authorized assets first; a downloadable original can exceed the transcoded HLS rendition. Keep tokens and signed download links private. This is not a public unauthenticated downloader API. |
| [yt-dlp plugin documentation](https://github.com/yt-dlp/yt-dlp#plugins) | The project states that plugins are imported even when not invoked and are not checked for safety. | Prefer the built-in generic HLS path; inspect plugin source, maintainer activity, and release artifacts before installing any extractor plugin. |

## Evidence limits

- GitHub stars/forks measure visible interest, not safety, correctness, support, or current compatibility.
- The Kinescope-specific project describes encrypted-video support and a decryption step. This research does not establish permission to decrypt any particular stream; the skill therefore uses ordinary accessible HLS or the user's authorized Kinescope API assets and stops at DRM restrictions.
- No maintained Kinescope-specific yt-dlp extractor plugin was identified in the repository/package search for this snapshot. The local yt-dlp extractor inventory also had no `kinescope` entry. Treat this as a search result, not proof that no such plugin exists.
- The current user's stream demonstrated that player metadata can return an HTML-escaped signed URL which yields 403 if passed through unchanged; the corrected manifest worked. This is an observed case, not a guarantee that every Kinescope 403 has the same cause.
